# Устройство офиса: модули сервера и сотрудники

> Как устроены модули `server/*`, сотрудники, отчёты, сторожа, планёрка, цели, память бизнеса, Telegram. Перенесено из CLAUDE.md 09.10.2026 дословно, ничего не сокращено.

## Модули

- `server/main.js` — точка входа. `config.js` — `data/config.json` (порт 3777, maxParallel 2, taskTimeoutMin 20, claudePath, telegram, переопределение `employees.<id>.model/effort`).
- `server/employees.js` — состав (ROSTER), все активны: manager, smm, montazh, marketing, sales (Ерлан, аналитик продаж), revenue (Нурлан, аналитик выручки). Системные промпты — `employees/<id>.md`.
- `server/claude.js` — поиск claude.exe на Windows (`.cmd` нельзя запустить без shell, а shell ломает многострочный промпт, поэтому запуск идёт через node + cli.js). Также аргументы запуска, окружение, запуск процесса, понятные русские ошибки.
- `server/office.js` — планы, очередь, зависимости, папка задачи `work/<taskId>/`. Руководитель помнит разговор: `conversation()` добавляет в промпт работу, на которую владелец ответил в Telegram (`about`), готовые задачи за 3 дня (кто, что, файлы, итог) и 5 последних реплик. На вопрос о сделанном он отвечает сам (`reply`, статус плана `replied`, в Telegram «💬 Руководитель»), без плана и утверждения. Бот хранит id своих сообщений о результате (`task.tgMessageIds`), поэтому ответ на текст или файл результата привязывается к задаче:
  - `_база` — копия `knowledge/`;
  - `_материалы` — вложения;
  - `_от_коллег` — результаты шагов-зависимостей.
- `server/store.js` — `data/state.json` и журнал событий `data/events/<id>.jsonl`. `server/activity.js` — описания действий инструментов по-русски.
- `server/render.js` — картинки: после задачи сотрудника с `render: true` (сейчас SMM) каждый `*.html` в папке задачи превращается в PNG через headless Chrome/Edge (`--screenshot`, `--virtual-time-budget` ждёт шрифты). Размер — из `<meta name="size" content="1080x1350">`. `{{ASSETS}}` в HTML заменяется на путь к `knowledge/ассеты` (эта папка в `_база` не копируется). Зависимостей нет.
  - **Автопроверка макетов (12.10.2026):** `checkHtml` открывает макет в том же Chrome (`--dump-dom`, окно на 300 px выше макета) со своим скриптом-проверкой (CSP с nonce: скрипты сотрудника по-прежнему запрещены) и возвращает список проблем по-русски: текст за краем (по объявленному размеру), закрыт другим блоком (`elementFromPoint` в 5 точках, точки сверху/снизу отступают на 30 % высоты строки), наезд текста на текст (прямоугольники ужаты на 20 % по высоте, пересечение > 20 %), обрезан в блоке с `overflow:hidden`, шрифт < 16 px, крупный текст в нижних 220 px сторис. Блок с `data-cover-ok` может закрывать текст нарочно (здание в приёме «текст за домом»). Не больше 12 пунктов.
  - `office.reviewDesign` после `renderMockups`: проверка бесплатна; если что-то нашлось — **один** дополнительный запуск того же сотрудника в той же папке (не больше 15 ходов) с перечнем «файл: проблемы» и правилами починки (один столбец flex, без absolute для текста), затем перерисовка и повторная проверка только этих файлов. Итог — строкой в результате задачи («✅ Автопроверка: исправлены наезды…» или «⚠️ Автопроверка: проверьте макеты — …»), стоимость правки добавляется к задаче. Выключатель: `data/config.json` → `"designCheck": false`.
  - Правила и шаблоны для Мадины — на сервере в `knowledge/картинки-стиль-и-правила.md` (раздел «Без наездов») и `knowledge/шаблоны/` (новые: `пост-4x5-визуал-и-факты.html` — основной для постов, `карусель-4x5-слайд-факты.html`, `сторис-9x16-опрос.html`; все 7 шаблонов проходят проверку). Старые версии — `/var/backups/ai-office/knowledge-design-before-2026-10-12.tgz`.
- `server/montage.js` — монтаж (сотрудник с `montage: true`, сейчас montazh). До запуска офис делает раскадровку каждого видео из `_материалы` в `_раскадровка/видео-N.jpg` (сетка 6 колонок, на кадрах подписаны секунды; drawtext на Windows падает без fontfile — ffmpeg запускается из папки Fonts). Монтажёр (только Read/Write/Glob) смотрит сетки и пишет `монтаж.json` {clips:[{file,start,duration}], lines, date}. После — офис собирает `reel.mp4` 1080×1920, 30 fps, с тихой звуковой дорожкой (без неё Telegram показывает ролик как GIF; в Telegram видео уходят через sendVideo): куски подряд + надписи как в примере владельца (белый Unbounded на красных плашках, печатается по буквам; дата жёлтым справа). Эффект печати: один прозрачный PNG-«спрайт» с полосами-шагами из Chrome, ffmpeg листает его `crop` с y от t. Без видео задача падает сразу, без запуска Claude. Пример владельца — `Примеры монтажа/` (в git не попадает).
- `server/meta.js` — Meta Graph API (v23.0, только чтение) для маркетолога (`meta: true`). Токен пользователя системы — в `data/config.json` → `meta`, вводится в ⚙ (офис сам находит Instagram через `me/accounts` и кабинеты через `me/adaccounts`). Перед запуском аналитика офис кладёт в `_данные/` `instagram.json` (итоги этой/прошлой недели, подписчики по дням, посты за 2 недели с охватом), `реклама.json` (объявления за 2 недели по `level=ad`) и картинки 6 лучших постов и 8 креативов по расходу. Ещё `настройки.json` (`collectSettings`): как запущено каждое объявление — цель кампании, бюджет (Meta отдаёт в центах), оптимизация, куда ведёт, аудитория (города/радиус, возраст, пол, интересы, Advantage+), места показа, даты, кнопка; по ним Алия пишет в отчёте разбор настроек и пошаговую инструкцию запуска по экранам Ads Manager, а на задачу «как запустить» с креативом в `_материалы` — файл `настройка.md`. Токен сотруднику не передаётся. Метрики Instagram — `views`/`reach`/`total_interactions` (impressions убраны Meta в 2025); неподдерживаемые метрики запрашиваются по одной и пропускаются. Проверено с настоящим токеном 02.10.2026: Instagram @your_company и кабинет 000000000000000 (USD, принадлежит портфолио «Диас таргетолог», в Altyn Qala — как партнёр) читаются; `follows_and_unfollows` без breakdown приходит пустым. Пользователь системы `office-reader` в портфолио Altyn Qala Group (ID 000000000000000), приложение Altyn Qala Office, только права на просмотр. WhatsApp в токен сознательно не добавлен.
- `server/sales.js` — данные для Ерлана и Нурлана (сотрудник с `sales: true`), чистым кодом до запуска Claude, в `_данные/`: `шахматка.json` (summary + все квартиры), `продажи.json` (8 недель по неделям: брони, снятые брони, продажи, известная выручка; все смены статусов; продажа = «Продана»/«Рассрочка», переход Рассрочка→Продана — не новая продажа), `реклама.json` (кампании Meta за 30/90 дней и объявления за 30, парк-проект исключён), `крыша-расход.json`. Выгрузки владельца из `_материалы` (WhatsApp `.txt`/`.zip`, Крыша `.csv`/`.xlsx` — свои zip и xlsx-читалка без зависимостей) обезличиваются в `_данные/клиенты/`: отправители → «Менеджер»/«Клиент», имена в тексте → [имя], телефоны/почта/ИИН/длинные номера → метки, столбцы с именами и телефонами удаляются; исходники стираются, Claude их не видит. Первые отчёты 06.10.2026: Ерлан ≈$0.45, Нурлан ≈$0.28.
- `server/payments.js` (09.10.2026) — выручка = полученные деньги. Офис ничего не вводит и не хранит: оплаты читает из шахматки `GET /api/analytics/payments` (портал Altyn Qala, `app/api/analytics/payments/route.ts`, без личных данных): по сделке `booking` {amount, date} (входит во взнос), `down_payment` {amount, date = начало рассрочки}, `payments[]` (due_*/paid_*), `overdue`, `next_due`. `moneyEvents`: бронь в свою дату, взнос минус бронь в дату начала, оплаченные строки по `paid_date`, будущие неоплаченные — `planned`; «Продана» без взноса и оплат — авто «полная оплата» (цена − бронь, дата продажи). `received(from, to]`, `planned`, `unfilled` (бронь без суммы, рассрочка без взноса и оплат), `deals`. Если выдача недоступна — `board.pay = null`, считаются только «Продана». `dashboard.withCash` в `live()` подменяет `revenue` недель/периодов/месяца, сумма договоров — в `contract`; `board.cash` (received, planned, next30, restOfMonth, unfilled, overdue, linked). «Почему изменилась» — разложение по видам платежей; прогноз месяца = факт + график до конца месяца + темп новых взносов. Нурлан получает `_данные/оплаты.json`. Деньги вне шахматки (другая очередь, другие проекты) — `data/extra-income.json` {items:[{date, amount, kind, label}]}. **Одно правило (19.11.2026, аудит, волна 1):** они **не входят** ни в выручку, ни в сравнения, KPI, «почему изменилась», факт/прогноз месяца и цель, метрики решений и цифры Диаса — `moneyEvents` их не содержит; показываются только отдельной строкой «Отдельно, вне шахматки» (`board.cash.extra`, `extraIncome()`), у Диаса — строкой «Вне шахматки … НЕ входит», у Нурлана — `вне_шахматки_не_в_выручке` в `оплаты.json`. Если выдача оплат не ответила: `board.payError`, `cash.payments = 'unavailable'`, `cash.unavailable` = «шахматка не ответила (оплаты)…», `unfilled` пустой (владельца не просим «внести оплаты»), заметка `Оплаты шахматки: …` в `notes` → утренняя строка не пишет «Спокойно», плитка «Деньги» серая «нет данных · оплаты не прочитались» (без суммы: без оплат «Продана» считалась бы целиком в день продажи — это завышение, а не полученные деньги); KPI «Выручка» = `null`, у целей и прогноза месяца выручка `null`, в «почему изменилась» процент не считается, Диасу и Нурлану — «посчитано по ценам проданных квартир, может быть завышено». «Продана» с частичной оплатой: `shortPaid()` → `cash.short` [{n, price, paid, planned, short}] и `продана_не_доплачено` у Нурлана (показ списком — волна 2). `undatedMoney()` — «Продана» без оплат и без даты продажи (деньги не попадают ни в один месяц). Первая запись 12.10.2026: N ₸ от 05.10.2026, Altyn Qala 2, 1 очередь (последняя квартира, полная оплата). Напоминание: `watchTeam` при смене статуса на Бронь/Рассрочка/Продана → `initiative.emit('pay')` → бот «впишите в шахматке» с кнопкой-ссылкой на шахматку (ключ `pay:<id>` в `seen`).
- `server/smm-pack.js` (12.10.2026) — «Пакет недели» Мадины и автопубликация Instagram. Пакет собирается из `пакет.json` (правило в `employees/smm.md`: писать всегда, когда готовит публикации; картинки могут лежать в `_от_коллег`) — и по контент-плану, и из любой её переделки; новый пакет заменяет прежний (`superseded`: невышедшие пункты и его предложение). В Telegram: альбом → по сообщению на день с полными текстами → «✅ Утвердить неделю / ✏️ Исправить день (`kf`→ выбор дня `kd` → правка ответом, `packFix`) / ✖️ Не публиковать». `fixDay` ставит Мадине задачу `source: 'pack-fix'` с `dependsOn` на задачи, где реально лежат картинки (в т.ч. вложенные `_от_коллег/<…> — t-…`), пункты дня → `fixing`; `applyFix` заменяет день: до утверждения недели → `waiting`, после → `day-review` и сообщение «✅ Утвердить день (`ky`) / ✏️ Исправить ещё». Дальше: когда обе задачи Мадины из утверждённого контент-плана готовы, `onTask` собирает пакет из их `пакет.json` ({items:[{date, time, type: post|story, images:[*.png], caption, sticker}]}; карусель = несколько images) + слоты рилсов из `контент-план.json` Алии → `data/smm-packs.json` и предложение `kind: 'smm-pack'` (срочное; в Telegram — альбом-превью и кнопки «Утвердить пакет / Не публиковать»; в портале SMM — карточка «Пакет недели»; в события и память не попадает). `initiative.decide` → `emit('smm-pack')` → пункты `scheduled` (прошедшее время → `late`). `tick` раз в минуту: пункт пришёл по времени (не позже 6 ч) → `publish`: PNG → JPEG ffmpeg во временную папку `data/smm/pub/<24 hex>/` (публичный путь портала `/pub/…` без входа, `publicFile`), `meta.post` контейнер (`STORIES` / карусель из детей `is_carousel_item`) → ждём `status_code FINISHED` → `media_publish` → permalink, папка удаляется; в Telegram — «Вышел пост / Вышла карусель» (сторис молча). Ошибка: 3 попытки, право доступа — сразу `failed` с подсказкой. Сторис с наклейкой и рилсы — `reminded`: напоминание в Telegram (сторис — с картинкой). `morningCheck` в 08:30: вчерашние пункты против `{ig}/media` и `{ig}/stories` — пишет, только если что-то не вышло. Выключатель: `data/config.json` → `smm.autopublish: false`. Требуется у токена Meta право `instagram_content_publish` (пользователь системы с доступом «Контент» к странице и Instagram).
  - Видео и время (17.11.2026): `readItems` ставит время сам (`slot`: сторис 12:00 + минуты по дню недели [вс..сб] = 4,0,5,3,7,2,6; посты/карусели 19:00 + 2,4,1,6,3,0,5; k-й пункт того же вида в день +40 мин; `cfg.smm.times` — свои слоты, `false` — время Мадины) и запоминает `html` макета для одиночной картинки. После утверждения (`decide`, `approveDay`) и на каждом `tick` — `makeVideos`: по одному, ближайшие сначала, только `scheduled`, не позже чем за 3 мин до выхода → `server/motion.js makeVideo` → `data/smm/video/<id>.mp4` (`x.video`, `x.music`); ошибка → `x.videoError`, одно сообщение «выйдет картинкой». `publish`: есть видео → `videoContainer` (сторис: `STORIES` + `video_url`; пост: `REELS` + `video_url`, `cover_url` = JPEG утверждённой картинки, `share_to_feed`), ожидание до 5 мин; любая ошибка, кроме прав, → `x.videoError` и публикация картинки (`pictureContainer`). `tick` не запускается повторно, пока идёт публикация (`ticking`). `/pub/` отдаёт `.jpg` и `.mp4` с `Content-Length`, `Range` (206/416) и `HEAD` (`http.js sendFile`). `morningCheck` не считает свои видео-посты рилсами маркетологов. Выключатель видео: `smm.video: false`; свои треки: `smm.music: [{id, title, start, url?}]`. Видео старше 21 дня и брошенные публичные копии `/pub` старше часа удаляются при запуске. Новый пакет заменяет пакет на утверждении целиком, а утверждённый — только на своих датах (четверговый пакет на следующую неделю не останавливает текущую; в портале видны обе). Статус «вышло» сохраняется сразу после `media_publish` (перезапуск не опубликует второй раз); если Instagram отказал на `media_publish` видео — публикуется картинка. Пункт, утверждённый перед самым временем, ждёт своё видео до 20 мин. Старые пакеты (до 17.11) при запуске получают макеты и слоты (`upgrade`); `server/pack-moves.json` — разовые переносы по просьбе владельца (`{id, type, to: "ГГГГ-ММ-ДД ЧЧ:ММ"}`, применяются один раз, первая невышедшая сторис/пост последнего пакета; первый — сторис 18.11 на 17.11 16:15).
  - `server/motion.js` (17.11.2026): Chrome через `--remote-debugging-pipe` (fd 3/4, без портов и пакетов), отдельный временный профиль; страница — макет с той же CSP, что у `render.js` (скрипты макета не работают), анализатор запускается через DevTools: находит блоки (картинки, тексты, плашки, «чипсы»), идёт сверху вниз рядами и даёт каждому появление через Web Animations (только `opacity`, `translate`, `scale`, `clip-path`, `object-view-box` — свои `transform` макета не трогаются): текст выезжает, плашка/чипс «выпрыгивает» (чипсы пульсируют на 6 и 11,5 с), фото открывается снизу и медленно приближается до 13,5 с, крупные числа (кроме годов) набегают с фиксированной шириной. Кадр за кадром: `__seek(t)` → `Page.captureScreenshot` (JPEG) → ffmpeg (`image2pipe`, H.264 yuv420p, AAC 48 кГц 128k, громкость −16 LUFS, `+faststart`), 15 с × 30 к/с. Проверка: последний кадр против утверждённого PNG (`ssim` ≥ 0,97), иначе видео удаляется и выходит картинка. Музыка — `TRACKS` (Mixkit, лучший 15-с кусок по громкости), скачиваются при первом использовании в `data/music/`, ротация «давно не звучал, не из последних трёх» — `data/smm/music-used.json`. Локально: ~30 с на видео; на сервере ожидается 1–1,5 мин.
- `server/ads-archive.js` (13.10.2026) — долгая память Алии о рекламе.
