- `start.bat` перезапускает офис через 10 с, если он упал (выход с ошибкой); `main.js` пишет сбои в `data/crash.log` (`unhandledRejection` не роняет процесс, `uncaughtException` — сохранить состояние и выйти на перезапуск).
- Простой сервера 08–16.11.2026 и что из него следует: оплата hoster.kz кончилась 08.11 — сервер работал, но был отрезан от сети (ни портала, ни SSH, ни Telegram/Meta/Claude); после оплаты 12.11 сеть вернулась, но (1) Caddy упал при загрузке: не смог разрешить `localhost` через DNS хостинга (в `/etc/hosts` хостинговый one-contextd оставил только `127.0.0.1 cloud-001…`), а сам Caddy после сбоя не перезапускается; (2) вход Claude Code на сервере истёк («OAuth session expired and could not be refreshed» — обновить вход без сети не вышло), и все запуски сотрудников падали, отчёты понедельников 09.11 и 16.11 не вышли. Исправлено 16.11: `127.0.0.1 localhost` добавлен в `/etc/hosts` (копия `/etc/hosts.bak-2026-11-16`), `/etc/systemd/system/caddy.service.d/restart.conf` — `Restart=on-failure`, `RestartSec=15`, без лимита попыток; вход Claude владелец сделал заново (`ssh … -t "sudo -u office -i claude"` → `/login`, ссылку открывает владелец, код вводит сам); отметки недели в `data/initiative.json` (`reportsWeek`/`directorWeek`/`lastWeek`) сброшены на W46, чтобы цепочка понедельника прошла заново (копия до правки — `/var/backups/ai-office/initiative-before-rerun-2026-11-16.json`). Если снова «Failed to authenticate» в `journalctl -u ai-office` — повторить вход тем же способом.
- Демо REVION (16.10.2026, `demo/server.js`): отдельный процесс без доступа к офису, данным и боту; отдаёт только файлы `portal/` и `web/img/team/` (выход из папки — 404, проверено), данные — только выдуманные из `demo/data.js`, POST ничего не меняют, заголовки `noindex` и `nosniff`.
- Самообновление на сервере (с 09.10.2026): `tools/auto-update.sh` по таймеру раз в 3 мин; новая версия ставится только если все файлы сервера проходят проверку синтаксиса и ни один сотрудник не работает; если после перезапуска офис не отвечает 20 с — откат на прошлую версию, сломанная больше не пробуется. Скрипт обёрнут в `main()`, потому что `git reset` переписывает его самого во время работы.
- HTTP: кривой URL → 400, а не падение; ошибки чтения/записи файлов не роняют сервер; недокачанная загрузка удаляется; имена файлов вроде `NUL.jpg` экранируются.
- Очередь: сбой в `finishTask` не занимает слот сотрудника навсегда; при «Закончился лимит подписки» задача возвращается в очередь, очередь стоит до сброса окна (`fiveHourResetsAt`), в Telegram одно сообщение ⏸; `tick` раз в минуту.
- Telegram: без сети при старте — повтор с паузой до 5 мин (не только 401); код привязки — 5 неверных попыток с чата, дальше он игнорируется.
- `initiative.json` пишется через tmp+rename с `.bak`, битый файл сохраняется как `.broken-<время>.json`. Недельные отчёты и планёрка догоняются в первый рабочий день недели, если в понедельник компьютер был выключен.
- Клиентские данные: любые `.txt/.zip/.csv/.xlsx` и прочие файлы-выгрузки (`DATA_RE`) обезличиваются для **всех** сотрудников (`cleanExports` в `prepareWorkspace`; аналитикам — в `_данные/клиенты`, остальным — на месте, картинки и видео остаются); выходные файлы без имён (`файл-N`), руководитель видит «выгрузка клиентов №N (имена скрыты)». Распознаются форматы Android/iPhone (невидимые метки направления)/ISO, склонения имён, телефоны KZ и городские, международные; шапка таблицы — первая строка с ≥3 ячейками, имена из удалённых столбцов вычищаются и из остальных; непонятный формат чата — файл не передаётся (fail closed); PDF, картинки и прочее аналитикам не передаются.
- `server/cleanup.js` раз в сутки: из `inbox` выгрузки клиентов через 7 дней и всё через 180; в `work/<задача>` рабочие копии (`_материалы`, `_данные`, `_база`, `_от_коллег`, `_раскадровка`) через 30 дней (результаты остаются); журналы событий через 180 дней.
- Рендер макетов: в HTML вставляется CSP (`default-src 'none'`, картинки только `file:`/`data:`, шрифты Google) — страница не может ничего отправить в интернет и не выполняет скрипты. Флаг `--blink-settings=scriptEnabled=false` не использовать: с ним Chrome не сохраняет скриншот. Автопроверка макетов (`checkHtml`) запускает только свой скрипт по одноразовому nonce в CSP — скрипты сотрудника заблокированы так же.
- Все запуски Claude (задачи, руководитель, инициатива, обучение) идут через общий лимит `setClaudeLimit(maxParallel + 1)` в `claude.js`; лишние ждут очереди. Pid каждого запуска пишется в `data/pids.json`, при старте `reapOrphans()` останавливает оставшиеся после сбоя (только процессы с `--no-session-persistence` в командной строке — чужой процесс с тем же pid не тронет). Зависший Chrome рендера убивается всем деревом.
- Telegram: неотправленное из-за сети (сообщения и файлы) ждёт в `data/outbox.json` и уходит после ближайшего успешного `getUpdates`; offset хранится в `data/telegram-offset.json` (после перезапуска сообщение не обрабатывается дважды); на 429 ждём `retry_after`.
- `state.json` раз в 10 мин копируется в `state.json.bak`; битый файл откладывается как `.broken-<время>.json` и берётся резервная копия. Планы, стоявшие в очереди при выключении, помечаются «Попробовать снова».
- Сотрудники не могут читать файлы вне своей папки задачи: `--restricted` ограничивает Read/Glob/Write рабочей папкой (проверено 06.10.2026: Read `../../data/…` → «outside … --restricted confines the file tools to the working directory»). Поэтому всё нужное сотруднику офис копирует в папку задачи сам.
- Не сделано: перенос под другую компанию (`data/company.json` с названием, городом, часовым поясом, валютой, фильтром кампаний, статусами продаж и расписанием).
